## 📥 كيفية التحميل

1. زيارة [صفحة التطبيقات](https://abosalehg-ui.github.io/my-apps/)
2. اختيار التطبيق المطلوب
3. الضغط على **"تحميل APK"**
4. (اختياري) التحقق من الملف: افتح «التحقق من الملف قبل التثبيت» تحت زر التحميل وقارن بصمة SHA-256 بالملف اللي نزل
5. تثبيت الملف على جهازك

> ⚠️ **ملاحظة:** قد تحتاج لتفعيل "التثبيت من مصادر غير معروفة" في إعدادات جهازك

كل التطبيقات موقّعة بنفس الشهادة، وبصمتها (SHA-256):

```
1f0b98e8d00eeec9b8d023661730483db6b45db94be130eedaa63edbb60da394
```

إذا عندك `apksigner` تقدر تتأكد منها بـ `apksigner verify --print-certs app.apk`.

## 📁 هيكل المشروع

```
my-apps/
├── index.html              # مُولَّد — لا تعدّله يدويًا
├── data/
│   └── apps.json           # مصدر الحقيقة: بيانات التطبيقات السبعة
├── tools/
│   ├── template.html       # هيكل الصفحة
│   ├── build.mjs           # يتحقق من البيانات ثم يبني index.html وأقسام README
│   ├── optimize-images.mjs # يحوّل اللقطات إلى WebP ويجرّد بياناتها الوصفية
│   └── apk-info.mjs        # يطلع SHA-256 للملف وبصمة شهادة التوقيع
├── assets/
│   ├── styles.css
│   ├── app.js              # تحسين تدريجي فقط — الصفحة تعمل بدونه
│   ├── fonts/              # خط Tajawal مستضاف ذاتيًا (SIL OFL)
│   └── screenshots/        # <slug>-<n>-{320,720,1080}.webp
├── .github/workflows/ci.yml
├── package.json
├── package-lock.json
└── README.md               # أقسام التطبيقات فيه مولَّدة أيضًا
```

> ملفات APK لا تُحفظ في المستودع (`.gitignore` يستبعد `*.apk`) — تُستضاف على Google Drive.

## 🧑‍💻 للمطوّرين

### التشغيل محليًا

```bash
git clone https://github.com/abosalehg-ui/my-apps.git
cd my-apps
python3 -m http.server 8000     # ثم افتح http://localhost:8000
```

الصفحة ثابتة بالكامل ولا تحتاج خطوة بناء لتُعرض. خطوة البناء لازمة فقط عند تعديل المحتوى.

### إضافة تطبيق جديد أو تعديل تطبيق قائم

`index.html` وأقسام التطبيقات في هذا الملف **مُولَّدة** — أي تعديل يدوي عليها يضيع في أول بناء. المصدر هو `data/apps.json`.

1. أضف عنصرًا جديدًا إلى مصفوفة `apps` في `data/apps.json`:

```json
{
  "id": "my-app",
  "name": "اسم التطبيق",
  "version": "1.0",
  "category": "tools",
  "icon": "🛠️",
  "iconClass": "editor",
  "tagline": "سطر تعريفي قصير",
  "description": "وصف من جملة أو جملتين.",
  "tags": ["🔒 ميزة", "⚡ ميزة"],
  "download": {
    "url": "https://drive.google.com/uc?export=download&id=...",
    "size": "12 ميجابايت",
    "sha256": "<64 حرف hex من npm run apk-info>"
  },
  "shots": [
    { "base": "my-app-1", "alt": "لقطة شاشة 1 من تطبيق كذا", "width": 320, "height": 700 }
  ],
  "features": [
    { "icon": "⚡", "title": "عنوان الميزة", "text": "شرح الميزة." }
  ]
}
```

2. ضع لقطات الشاشة في `assets/screenshots` باسم `my-app-1.png`، ثم:

```bash
npm install        # مرة واحدة
npm run images     # يولّد 320/720/1080 بصيغة WebP ويجرّد EXIF
```

احذف ملفات المصدر بعد التحويل، وحدّث `width`/`height` في `data/apps.json` لو تغيّرت نسبة الأبعاد.

3. احسب بصمة الملف (وكل ما رفعت إصدارًا جديدًا):

```bash
npm run apk-info -- path/to/my-app.apk
```

انسخ `sha256` إلى `download.sha256`. وقيمة `signer` لازم تطابق `signer` في أعلى `data/apps.json`. لو اختلفت، فالملف موقّع بمفتاح ثاني، ولازم تعرف السبب قبل النشر.

4. أعد بناء الصفحة والتزم بالنتيجة:

```bash
npm run build      # يكتب index.html وأقسام README
npm run check      # يفشل لو أي منهما غير مطابق للبيانات (نفس فحص CI)
```

البناء يتوقف برسالة واضحة إذا كانت `iconClass` غير معرّفة في `assets/styles.css`، أو `category` غير موجودة في التصنيفات، أو نقص حقل، أو الرابط مو `https://`، أو لقطة شاشة ناقصة، أو إذا استُعمل متغير CSS بدون تعريف.

### التكامل المستمر

`.github/workflows/ci.yml` يشغّل على كل دفعة: التحقق من البيانات ومتغيرات CSS وتطابق `index.html` و README، تدقيق HTML، فحص الروابط المكسورة، وLighthouse. عتبات Lighthouse في `.lighthouserc.json`. والإجراءات مثبّتة بالـ SHA، فحدّثها بقصد مو تلقائيًا.
